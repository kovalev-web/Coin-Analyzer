# Личный edge трейдера — журнал на данных

Документ для аналитика (человека или Claude в другом чате): как устроен журнал QuestTick,
каким данным верить, как они считаются и что в планах. Источник истины по определениям —
`journal/facts.js`; при изменении порогов обновлять и этот файл.

## Цель
Собирать **правдивые** данные о том, что реально влияет на результат трейдера, чтобы
находить личный edge и его утечки. Принцип: **факты считает система, человек отвечает
только на то, чего данные знать не могут, и в момент, когда это происходит.**

Почему: самооценка, заполненная вечером, страдает от
- **outcome bias** — после минусового дня «процесс» кажется плохим, после плюсового — хорошим;
- **recall bias** — триггеры и эмоции вспоминаются через часы, многое теряется;
- **самооправдания** — «объём был нормальный», «торговал по плану».

## Три слоя данных
1. **Факты** (система, из сделок Binance) — не редактируются человеком. ✅ Этап 1.
2. **Состояние** (человек, коротко, ДО результата): утренние шкалы и пометка сразу после сделки. ✅ Этапы 2–3.
3. **Выводы** (человек, вечер): только то, что данные не знают. ✅ Этап 4. Отчёт «My edge» — ✅ этап 5.

## Этап 1 — факты дня (сделано 2026-10-25)
Модуль `journal/facts.js` (тесты `npm run test:journal`), эндпоинт `GET /api/journal/facts?date=YYYY-MM-DD`.
Снимок фактов сохраняется в `journal_entries.facts_json` при сохранении вечерней карточки;
`trade_count` и `pnl` этой записи берутся из фактов, а не из ввода.

**Источник сделок:** для торгового аккаунта на live — ключ trader (`/history/trades`, `/history/income`),
иначе — read-only ключ дневника. Монеты дня находятся по записям `COMMISSION` (по одной на fill),
fills берутся за окно «сутки до начала дня … конец дня», считаются только сделки, **открытые** в этот день.

**«День»** — календарная дата в часовом поясе пользователя (`account_tz`, иначе `briefing_tz`, иначе UTC) —
тот же день, что у брифинга и журнала.

### Определения
| Поле | Как считается |
|---|---|
| **Сделка (trade)** | round trip по символу: позиция 0 → ≠0 → 0 (one-way). Доливки и частичные выходы внутри — одна сделка. Fill, переворачивающий позицию через 0, закрывает одну сделку и открывает следующую |
| `pnlNet` | Σ realizedPnl − Σ commission (только комиссии в USDT) |
| `result` | `win` если pnlNet > 0, иначе `loss`; `open` если позиция не закрыта к моменту расчёта |
| `holdSec` | закрытие − открытие |
| `maxNotional` | максимальный \|позиция\| × цена fill внутри сделки (размер позиции) |
| `planned` | символ есть в брифинге этого дня (не auto) |
| `atLevel` | цена входа в пределах **0.5 %** от любой цены алерта пользователя по символу; `null`, если алертов нет |
| `oversize` | `maxNotional` > дневной рабочий объём × **1.05** (лимит из Account settings) |
| `revenge` | вход в течение **5 минут** после закрытия убыточной сделки этого дня |
| `sizeUp` | `maxNotional` > **1.5 ×** медианы предыдущих сделок дня **и** две предыдущие закрытые сделки с одинаковым исходом → `after_wins` / `after_losses` |
| `afterCrane` | вход после **2 убыточных сделок подряд** (правило «стоп-кран») |
| `hour` | час открытия в часовом поясе пользователя |

`violations`: `craneBrokenAt` (время первого входа после стоп-крана), `tradesAfterCrane`, `overMaxTrades`,
`oversize`, `revenge`, `sizeUpAfterLosses`, `sizeUpAfterWins`, `offPlan`.

### Чему верить аналитику
- **Факты > самооценка.** Поля вечерней карточки `tradeCount`, `pnl`, `stopCraneKept`, `volumeOk`,
  `tradedPlanned` — самооценка; при расхождении с `facts` верны факты.
- Записи журнала **до 2026-10-25** фактов не имеют — для них есть только самооценка и
  агрегаты по сделкам монет из брифинга (старый расчёт).
- Делать выводы только при достаточной выборке: ориентир ≥ 20 сделок в группе сравнения,
  всегда указывать n.
- Ограничения: комиссии не в USDT (BNB) не учитываются; `atLevel` знает только текущие алерты
  (сработавшие и удалённые алерты в прошлом могут отсутствовать); лимиты берутся текущие, не на дату.

## Этапы 2–5 (сделано 2026-10-25)

### 2. Утренняя карточка v2
Поля (`journal_entries`): `sleep_hours` (REAL), `sleep_quality`, `energy`, `carryover` («несу вчерашнее»,
1 = ничего, 5 = тяжело), `focus` — шкалы 1–5; `if_then` — JSON `{if, then}`, правило дня.
Подсказка «Yesterday you wanted to fix: …» берётся из `fix_tomorrow` последнего вечера.
Старое `morning_state` больше не спрашивается (остаётся в истории до 2026-10-25), `trigger_watch` заменён `if_then`.
Подсказка «Risk zone» показывается при энергии ≤ 2, качестве сна ≤ 2 или «несу вчерашнее» ≥ 4.

### 3. Пометка после сделки
Таблица `trade_tags (user_id, symbol, close_time, setup, emotion)`, `close_time` — время биржевого fill закрытия.
`setup`: `A` / `B` / `C`. `emotion`: `plan` (спокойно, по плану) / `fomo` / `revenge` / `boredom` / `fear`.
Ставится в стакане сразу после того, как позиция стала 0 (можно пропустить), либо в вечерней карточке
у сделок без пометки. `POST /api/journal/trade-tag` (частичные пометки сливаются).
Связь со сделкой из фактов: тот же символ, ближайшая неиспользованная пометка в пределах **2 с** от `closeTime`.

### 4. Вечерняя карточка v2
Блок фактов (только чтение, с пометками сделок) + вопросы только о том, чего данные не знают:
`why_breaks` (обязателен, если в фактах есть нарушения), `did_well`, `fix_tomorrow` (обязательны),
`self_talk` после убытков: `harsh` / `neutral` / `kind` (обязателен, если были убыточные сделки),
`missed_screening` (опц.), `evening_state` 1–5, `free_conclusion` (опц.).
Убраны самооценки, которые теперь считаются: процесс 1–5, «по плану», количество сделок, стоп-кран,
объём, триггеры-пилюли, «чувствовал бесполезность» (заменено `self_talk`). В истории до 2026-10-25 они есть.

### 5. Отчёт «My edge»
`journal/edge.js` (тесты), `GET /api/journal/edge?range=1m|3m|6m|all`, раздел на странице Journal.
Берёт закрытые сделки из `facts_json` (дни с сохранённой вечерней карточкой) × пометки × утреннее состояние дня.
Группы: качество сетапа, эмоция входа, нарушения (clean / revenge / size-up / после стоп-крана / сверх объёма —
приоритет в этом порядке: after stop-crane > revenge > size-up > over volume), план (в брифинге / вне),
у сигнального уровня, сон (< 6 / 6–7.5 / 7.5+ ч), качество сна / энергия / «несу вчерашнее» / фокус
(низко 1–2 / средне 3 / высоко 4–5), час входа блоками по 4 часа.
По каждой группе: n, win rate, PnL, средний PnL; `enough = n ≥ 20`, меньше — «пока мало данных».
AI-отчёт получает эти группы и новые поля карточек.

### Что ещё стоит сделать (идеи)
- MAE/MFE по сделке (нужны свечи) — насколько рано выходит/поздно режет.
- R-multiple, если известен стоп на входе (стоп из algo-ордера).
- Недельный обзор «что одно изменить» на основе edge-групп с n ≥ 20.

## Контекст трейдинга
- Торговля: Binance USDⓈ-M фьючерсы через брокера Tiger.com (возврат комиссии), скальпинг, стакан QuestTick.
- Лимиты риска (дневной убыток и т.п.) настроены у брокера; в QuestTick — рабочий объём, % просадки
  на сделку, макс. сделок (Account settings), используются для фактов.
- Флоу дня: утренняя карточка открывает терминал → сделки по сигналам (алерты по уровням) →
  вечерняя карточка закрывает терминал до следующего дня (нельзя при открытой позиции/заявке на вход).
